# Review of the MVP (2026-09-03)

Four reviewers (Slack semantics, engineering standards, tests, robustness) and
two adversarial verifiers per finding: 27 findings, 6 confirmed by both
verifiers, 21 contested (one verifier judged them immaterial in practice).

## Confirmed and fixed

1. Form parsing JSON-parsed any field starting with `[` or `{`, so a message
   `text` that looked like JSON was mangled. Now only the fields the SDKs
   JSON-stringify are parsed (`blocks`, `attachments`, `metadata`, `files`,
   `view`, `prompts`, `icons`, `user_ids`, `types`, `chunks`,
   `loading_messages`). Regression test in `test/admin-api.test.ts`.
2. `response_url` with `replace_original` / `delete_original` on an ephemeral
   message returned HTTP 500. Ephemeral targets are now updated or removed in
   place, and Slack errors come back as `{ ok: false, error }`.
3. `view_submission` ignored `response_action`. `errors` keeps the modal open,
   `update` swaps it, `push` stacks a new view, `clear` closes all, an empty
   ack closes the view.
4. Dead code removed (`page()`, `tsToDate()`); `views.update` now emits the
   `view.update` change.
5. `test/store.test.ts` depended on an absolute path to the agent-swarm
   checkout. The manifest is now a fixture in `test/fixtures/`.
6. Redelivery give-up after `maxRetries` was untested. Test added.

## Contested, fixed anyway (cheap and faithful)

- `conversations.archive` on `#general` returns `cant_archive_general`.
- Expired trigger ids are removed from the map on `views.open`.
- A corrupt JSONL journal line is skipped with a warning instead of aborting
  start-up.
- Malformed `view` JSON and malformed `response_url` bodies return Slack-shaped
  errors instead of 500s.
- Socket Mode tickets are consumed on upgrade.

## Contested, left as is (with the reason)

- Thread parents without `thread_ts`: agent-swarm never reads it on parents and
  the proposed fix broke `history` filtering.
- `message_changed` per streaming chunk: no evidence of Slack's real behaviour;
  agent-swarm ignores `message_changed`.
- Empty `state.values` in `block_actions`: no consumer reads it.
- Bot may delete other users' messages; `cant_delete_message` is available via
  `injectFault`.
- Redelivery on by default: Bolt acks events before listeners run, so only
  commands, actions and views that take longer than `ackTimeoutMs` (3s)
  see a redelivery, which is what Slack does too.
- `apiCalls`, `deliveries`, `responseUrls` are unbounded: test-scoped
  processes; a long-running `serve` can restart.
- `/mock/*` has no auth: it binds to loopback by default; do not expose it.
- `flush()` is a quiet-period heuristic (100ms): 30x margin in practice.
- Test hygiene items (try/finally in inline tests, `getFreePort` race).
