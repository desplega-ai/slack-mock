## Prior art

### slack-mock (Skellington-Closet)

- URL: https://github.com/Skellington-Closet/slack-mock
- Language: JavaScript (Node)
- Covers: Web API (returns {ok:true} or a queued custom response for every request), a websocket server mocking the legacy RTM API (rtm.start/rtm.connect), and Events API push simulation. Intercepts outbound HTTP to https://slack.com and https://hooks.slack.com so bot code needs no URL changes. No Socket Mode support (predates it), no message storage/JSONL, no HTML rendering.
- Verdict: borrow ideas -- its request-interception + queued-custom-response pattern for the Web API is a good model, and its 'mock every one of Slack's inbound/outbound channels' scope framing matches ours, but it targets the deprecated RTM API rather than Socket Mode and appears unmaintained (npm package at v1.1.1, MIT license); would need a from-scratch Socket Mode layer.

### slack-server-mock (ygalblum)

- URL: https://github.com/ygalblum/slack-server-mock
- Language: Python
- Covers: Combined HTTP + WebSocket mock server explicitly aimed at sub-system testing of Slack apps, including Socket Mode support (app points its WebClient base_url at the mock, e.g. http://localhost:8888). Provides an endpoint to inject a message toward the app under test and collect the app's (ephemeral) responses. Also published as a container image (quay.io) runnable via podman/docker.
- Verdict: borrow ideas -- architecturally the closest prior art (HTTP+WS, Socket-Mode-aware, bidirectional message injection/collection), but it's Python (poetry-based) so code can't be reused directly in a Bun/TS project; its endpoint design ('send message, wait for app response, return responses') is a useful pattern to mirror in slack-mock's test-injection API.

### slack-testing-library (chrishutchinson)

- URL: https://github.com/chrishutchinson/slack-testing-library
- Language: JavaScript/TypeScript (Node)
- Covers: A mock server + client library for integration-testing interactive Slack apps by replicating the Slack API server's behavior; provides an intercept() method for custom responses and testing error handling. Appears HTTP-receiver oriented (interactivity via HTTP), not confirmed to support Socket Mode.
- Verdict: borrow ideas -- worth reviewing its intercept()/custom-response ergonomics and any interactivity payload builders for shape reference, but does not appear to solve the Socket Mode or HTML-rendering pieces of our requirements.

### python-slack-sdk: mock_socket_mode_server.py / mock_web_api_server.py

- URL: https://github.com/slackapi/python-slack-sdk/blob/main/tests/slack_sdk/socket_mode/mock_socket_mode_server.py
- Language: Python
- Covers: Minimal Socket Mode WebSocket server and HTTP Web API mock server living inside the SDK's own test suite (used to test slack_sdk's client code, not for downstream app integration testing). Not published as a standalone package; MIT-licensed as part of the slack_sdk repo.
- Verdict: borrow ideas -- authoritative, maintained-by-Slack reference for exact wire-level message shapes (hello, envelope, ack, disconnect) since it's used to validate Slack's own official client; worth reading closely for edge cases, but needs full reimplementation to reuse in Bun/TS and to serve external test scenarios rather than SDK unit tests.

### bolt-python: tests/mock_web_api_server.py

- URL: https://github.com/slackapi/bolt-python/blob/main/tests/mock_web_api_server.py
- Language: Python
- Covers: http.server-based mock of the Web API used across bolt-python's scenario test suite (mirrors mock_web_api_server usage pattern from python-slack-sdk). HTTP-only; no Socket Mode, no storage, no rendering.
- Verdict: ignore for direct reuse (Python, internal test fixture only, HTTP-only) -- but same authoritative-reference value as the python-slack-sdk mock for confirming exact request/response field names per method.

### bolt-js (no dedicated Socket Mode mock exists)

- URL: https://github.com/slackapi/bolt-js/issues/803
- Language: TypeScript (Node) -- the framework itself, not a mock
- Covers: N/A as prior art for a mock; documents the gap. Multiple open issues (#803, #1343, #752, #2225) confirm bolt-js ships no test-mode Socket Mode receiver and the community workaround is to point apps.connections.open (via a stubbed Web API base URL) at a local mock WebSocket server.
- Verdict: ignore as a source of reusable mock code, but load-bearing as confirmation of the exact integration seam (apps.connections.open response -> WS URL -> bolt connects via the real `ws` client) that slack-mock must implement to be a drop-in Socket Mode target for agent-swarm's App({ socketMode: true }).

### slack-api-specs (slackapi/slack-api-specs)

- URL: https://github.com/slackapi/slack-api-specs
- Language: JSON (OpenAPI 2.0 for Web API, AsyncAPI for Events API)
- Covers: Machine-generated OpenAPI v2 spec of the public Web API (slack_web_openapi_v2.json) and an AsyncAPI spec of the Events API. Static schema/shape reference only -- no state, no Socket Mode, no interactivity payload catalog, no server behavior.
- Verdict: borrow ideas / reference only -- repo is archived (read-only since March 27, 2024, no PRs accepted), so it cannot be extended, but the JSON schemas are useful to validate our mock's HTTP response shapes against. No evidence found of anyone publishing a maintained WireMock/Prism mock built from it; would have to build that ourselves and it would still lack Socket Mode/interactivity/state, which are the hard parts.

### jsx-slack (yhatt)

- URL: https://github.com/yhatt/jsx-slack
- Language: TypeScript (Node)
- Covers: Builds Block Kit JSON *from* JSX -- the reverse direction of what the mock's HTML renderer needs (Block Kit JSON -> HTML). Actively maintained, has a public REPL/demo.
- Verdict: ignore for the mock server itself (wrong direction, and not a mock); its list of supported Block Kit components/props is a useful checklist when scoping which block types the HTML renderer must support.

### slackdown (datadesk) / slack-mrkdwn (gooody)

- URL: https://github.com/datadesk/slackdown ; https://github.com/gooody/slack-mrkdwn
- Language: JavaScript
- Covers: Small single-purpose libraries converting Slack's mrkdwn text formatting to HTML (bold/italic/strike/code/links/etc.), which is exactly the text-formatting sub-problem of rendering channel/thread HTML for screenshots (item (d) in scope).
- Verdict: borrow ideas / possible reuse for the mrkdwn-to-HTML leaf of the renderer -- confirm current maintenance status and license before adding as a dependency; likely simpler to port the small conversion ruleset directly given the narrow scope.
